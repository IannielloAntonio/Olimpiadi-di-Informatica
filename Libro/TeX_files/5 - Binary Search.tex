\chapter{Binary Search}


La \textbf{ricerca binaria} (o \emph{binary search}) è un algoritmo efficiente per individuare un elemento all'interno di una collezione di dati \textbf{ordinata} (ad esempio un array o una lista).

L'idea fondamentale della ricerca binaria si basa sulla strategia del \emph{divide et impera}: invece di controllare tutti gli elementi uno per uno (come avviene nella ricerca sequenziale), l'algoritmo confronta l'elemento cercato con quello centrale della struttura dati e, in base al risultato del confronto, elimina metà dello spazio di ricerca ad ogni iterazione.

Il procedimento è il seguente:
\begin{enumerate}
	\item Si considera l'elemento centrale dell'array.
	\item Se esso coincide con il valore cercato, la ricerca termina con successo.
	\item Se il valore cercato è minore dell'elemento centrale, si continua la ricerca nella metà sinistra dell'array.
	\item Se il valore cercato è maggiore dell'elemento centrale, si continua la ricerca nella metà destra dell'array.
	\item Il processo viene ripetuto finché l'elemento viene trovato oppure l'intervallo di ricerca diventa vuoto.
\end{enumerate}

Grazie a questa strategia, il numero di confronti cresce in modo logaritmico rispetto alla dimensione dei dati: la complessità temporale della ricerca binaria è infatti pari a \(\mathcal{O}(\log n)\), risultando molto più efficiente rispetto alla ricerca sequenziale, che ha complessità \(\mathcal{O}(n)\).

È importante sottolineare che la ricerca binaria può essere applicata esclusivamente a strutture dati ordinate; in caso contrario, l'algoritmo non garantisce la correttezza del risultato.

\bigskip 
\noindent\textbf{Esempio: ricerca del giorno di compleanno}

Si supponga di voler individuare il giorno del compleanno di una persona all’interno di un determinato mese.
Consideriamo un \texttt{vector} ordinato contenente tutti i giorni del mese:

\[
\texttt{giorni} = [1, 2, 3, \dots, N]
\]

dove $N$ rappresenta il numero di giorni del mese.
Il valore \texttt{compleanno} indica il giorno da individuare.

\medskip

Una prima strategia consiste nello scorrere linearmente il vettore confrontando ciascun elemento con il valore cercato:

\begin{lstlisting}[language=C++]
	// N = numero di giorni del mese
	// vector<int> giorni(N)
	// compleanno = giorno da indovinare
	
	for(int i = 0; i < N; i++){
		if(giorni[i] == compleanno){
			trovato = true;
			indice = i;
			break;
		}
	}
\end{lstlisting}

Questa soluzione presenta una complessità computazionale pari a:
\[
O(N)
\]
poiché nel caso peggiore è necessario controllare tutti gli elementi del vettore.

\medskip

È possibile migliorare questa strategia sfruttando il fatto che il vettore è ordinato.
Invece di chiedere direttamente:  
\emph{``Sei nato in questo giorno?''},  
possiamo formulare domande del tipo:  
\emph{``Sei nato prima del giorno $x$?''}, alle quali la persona può rispondere soltanto con \texttt{sì} o \texttt{no}.

In questo modo è possibile scartare, ad ogni passo, metà dei giorni ancora candidati.

\medskip

L’algoritmo mantiene tre indici:
\begin{itemize}
	\item \textbf{LOW}: indice del primo giorno considerato;
	\item \textbf{HIGH}: indice dell’ultimo giorno considerato;
	\item \textbf{MID}: indice centrale tra \textbf{LOW} e \textbf{HIGH}.
\end{itemize}

Inizialmente:
\[
\texttt{LOW} = 0, \quad \texttt{HIGH} = N - 1
\]

e:
\[
\texttt{MID} = \left\lfloor \frac{\texttt{LOW} + \texttt{HIGH}}{2} \right\rfloor
\]

Se il giorno del compleanno coincide con \textbf{MID}, l’algoritmo termina con successo.

Se alla domanda:
\begin{quote}
	``Sei nato prima del giorno \texttt{giorni[MID]}?''
\end{quote}
la risposta è \texttt{sì}, allora tutti i giorni successivi o uguali a \texttt{MID} possono essere scartati.
Si aggiorna quindi:
\[
\texttt{HIGH} = \texttt{MID} - 1
\]

Se invece la risposta è \texttt{no}, allora il compleanno si trova necessariamente dopo \texttt{MID} e si aggiorna:
\[
\texttt{LOW} = \texttt{MID} + 1
\]

A ogni iterazione l’intervallo di ricerca viene dimezzato.
Ripetendo questo procedimento si individua l’unico giorno possibile compatibile con le risposte fornite.

\medskip

La codifica risulta la seguente:

\begin{lstlisting}[language=C++]
#include <bits/stdc++.h>
using namespace std;

int main(){
	// Numero di giorni nel mese (ipotizziamo 30)
	int N = 30; 
	
	// Creiamo un vettore che contiene tutti i giorni del mese
	vector<int> giorni(N);
	
	// Riempimento del vettore: giorni[0] = 1, giorni[1] = 2, ..., giorni[29] = 30
	for(int i=0; i<N; i++){
		giorni[i] = i+1;
	}
	
	// Inizializziamo gli indici per la ricerca binaria
	int low = 0;        // primo indice del vettore
	int high = N-1;     // ultimo indice del vettore
	int mid = 0;        // indice centrale (verrà calcolato nel ciclo)
	
	int compleanno = 4; // il giorno del compleanno che vogliamo trovare
	int ans = -1;       // qui salveremo l'indice del giorno trovato (-1 significa "non trovato")
	
	// Ciclo principale della ricerca binaria
	// continua finché l'intervallo non è vuoto
	while(low <= high){
		// Calcoliamo l'indice centrale tra low e high
		mid = (high + low)/2;
		
		// Se il giorno centrale corrisponde al compleanno
		if(giorni[mid] == compleanno){
			ans = mid; // salviamo l'indice
			break;     // interrompiamo il ciclo, abbiamo trovato il giorno
		}
		
		// Se il giorno centrale è maggiore del compleanno
		// significa che il compleanno si trova nella metà sinistra
		if(giorni[mid] > compleanno){
			high = mid - 1; // aggiorniamo high per escludere la metà destra
		}
		else{
			// Altrimenti il giorno centrale è minore del compleanno
			// il compleanno si trova nella metà destra
			low = mid + 1;  // aggiorniamo low per escludere la metà sinistra
		}
	}
	
	// Stampa del risultato
	// giorni[ans] contiene il giorno trovato
	cout << "Sei nato il giorno: " << giorni[ans];
	
	// Nota: se il giorno non fosse presente nel vettore, ans resterebbe -1
	// e sarebbe meglio gestire il caso con un controllo
	// if(ans != -1) cout << giorni[ans]; else cout << "Giorno non trovato";
}

\end{lstlisting}


\medskip

\medskip



\noindent Poiché a ogni passo della ricerca binaria si scarta metà degli elementi ancora candidati, il numero di elementi da controllare può essere calcolato nel seguente modo:

\[
N \;\rightarrow\; \frac{N}{2} \;\rightarrow\; \frac{N}{4} \;\rightarrow\; \frac{N}{8} \;\rightarrow\; \dots \;\rightarrow\; \frac{N}{2^k} = 1
\]

Dove $k$ indica il numero di iterazioni necessarie per arrivare a un singolo elemento.  
Dal momento che \(\frac{N}{2^k} = 1\), ricaviamo:

\[
2^k = N \quad \Rightarrow \quad k = \log_2 N
\]

Quindi, nel caso peggiore, la ricerca binaria richiede $O(log_2 N)$ confronti.  
Questo è molto più efficiente della ricerca lineare, che richiede fino a \(O(N)\) confronti nel caso peggiore.

\section{Do not Gather!}

\href{https://training.olinfo.it/task/ois_gatherings}{Link al problema} 

\smallskip

\noindent Time limit = 1.00s, Memory limit = 256 MB

\bigskip

As vaccinations against COVID-19 are starting all over the world, people seem to keep forgetting the one
and only piece of advice they have been given in the last months: “Do Not Gather!”.

\medskip
To receive their dose, people usually queue up outside the administration center and form a line. Often,
though, the minimum interpersonal distance $D$ (measured in centimeters) imposed by law is not respected,
enabling possible infections.

\bigskip
Luca was walking and accidentally noted the troubling situation: out of $N$ people in queue at positions $P_i$, also measured in centimeters starting from the vaccination center, many seem to be in a risky position.
How many pairs of people do not respect the distance, i.e. the distance between them is less than the required distance?

\subsubsection*{Input}  

The first line contains two integers, $N$ and $D$. The second line contains $N$ integers $P_i$

\subsubsection*{Output}  

You need to write a single line with an integer: the number of pairs of people who do not respect the minimum distance.


\subsubsection*{Assunzioni e Vincoli}  


\begin{itemize}
	
	\item $1 \le N \le 100\ 000$
	
	\item $1 \le D\le 10^9$
	
	\item $0 \le P_i \le 10^9$
	
	\item  Positions are all distinct and are listed from the nearest to the farthest (i.e., $P_i < P_{i+1}$ for each $i =0 \dots N-2$)
	
\end{itemize}



\subsubsection*{Esempio}  

\begin{table}[h!]
	\begin{tabular}{|l|c|}
		\hline
		\multicolumn{1}{|c|}{Input}                                        & Output \\ \hline
		\begin{tabular}[c]{@{}l@{}}4  100\\ 20  120  200  300\end{tabular} & 1      \\ \hline
		\begin{tabular}[c]{@{}l@{}}4  200\\ 0  100  150  200\end{tabular}  & 5      \\ \hline
	\end{tabular}
\end{table}

\noindent\textbf{Spiegazione:} 

In the first sample case the second and the third person are at distance $200-120 = 80$ centimeters which is below $100$. All other pairs respect the distance.

\bigskip
In the second sample case there are five problematic pairs: the first and the second person (distance $100$), the first and the third one (distance $150$), the second and the third one (distance $50$), the second
and the fourth one (distance $100$) and the third and the fourth one (distance $50$).


\subsubsection*{Idea (binary search)}

Si fissa un elemento $P[i]$ del vettore come primo elemento della coppia.

Poiché il vettore $P$ è ordinato in modo crescente, la quantità $P[j] - P[i]$ cresce all’aumentare dell’indice $j$.
Di conseguenza, se per un certo indice $j$ risulta:
\[
P[j] - P[i] \ge D,
\]
allora la stessa disuguaglianza è verificata per tutti gli indici successivi $j' > j$.

Per ciascun indice $i$:
\begin{itemize}
	\item si ricerca, mediante ricerca binaria, il più piccolo indice $j$ tale che:
	\[
	P[j] - P[i] \ge D;
	\]
	\item tale indice individua il punto di separazione tra gli elementi che distano meno di $D$ da $P[i]$ e quelli che distano almeno $D$.
\end{itemize}

Tutti gli elementi con indice compreso tra $i+1$ e $j-1$ formano coppie valide con $P[i]$, mentre tutti quelli con indice maggiore o uguale a $j$ sono certamente a distanza almeno $D$ e quindi non validi.

Il numero di coppie valide associate all’indice $i$ è quindi:
\[
(j - 1) - i.
\]

Il procedimento viene ripetuto per ogni indice $i$ del vettore.

Infine, la somma di tutti i contributi ottenuti rappresenta il numero totale di coppie $(i,j)$ tali che:
\[
P[j] - P[i] < D.
\]


\subsubsection*{Implementazione C++ - Binary Search}


\begin{lstlisting}[language=C++]
// https://training.olinfo.it/task/ois_gatherings

#include <bits/stdc++.h>
using namespace std;

int main() {
	
	// Legge il numero di persone (dimensione del vettore)
	int N;
	cin >> N;
	
	// Legge la distanza minima D
	int D;
	cin >> D;
	
	// Vettore che contiene le posizioni delle persone (ordinato per ipotesi del problema)
	vector<int> P(N); 
	for(int i = 0; i < N; i++){
		cin >> P[i];
	}
	
	// Variabile che conterra' il numero totale di coppie valide
	int64_t coppie = 0;
	
	// Ciclo esterno: si fissa ogni elemento P[i] come primo elemento della coppia
	for(int i = 0; i < N; i++){
		
		// Limiti della ricerca binaria sugli elementi successivi a i
		int low = i + 1;
		int high = N - 1;
		int mid;
		
		// best memorizza l'ultimo indice valido trovato
		int64_t best = i;
		
		// Ricerca binaria per trovare il massimo indice j tale che:
		// P[j] - P[i] < D
		while(low <= high){
			
			mid = (low + high) / 2;
			
			// Se la distanza e' maggiore o uguale a D,
			// bisogna cercare nella parte sinistra
			if(P[mid] - P[i] >= D){
				high = mid - 1;
			}
			// Se la distanza e' minore di D,
			// mid e' un candidato valido e si prova a cercare più a destra
			else if(P[mid] - P[i] < D){
				best = mid;
				low = mid + 1;
			}
		}
		
		// Tutti gli indici compresi tra i+1 e best formano coppie valide con i
		// Il numero di coppie valide per questo i e' (best - i)
		coppie += best - i;
	}
	
	// Stampa il numero totale di coppie valide
	cout << coppie << endl;
	
	return 0;
}

\end{lstlisting}

\subsection*{Costo Computazionale}
Il costo computazionale è:
\begin{itemize}
	\item $O(\log N)$ per la ricerca binaria eseguita per ciascun indice $i$;
	\item $O(N)$ per il ciclo esterno che scorre tutti gli elementi del vettore.
\end{itemize}

Ciò significa che la ricerca binaria viene eseguita $N$ volte, una per ciascun elemento del vettore.

La complessità totale è quindi:
\begin{align*}
	&= O(N) \cdot O(\log N) \\
	&= O(N \log N)
\end{align*}

Dai vincoli del problema:
\[
1 \le N \le 10^5
\]

la complessità può essere stimata come:
\begin{align*}
	&\approx O(N \log N) \\
	&\approx O(10^5 \cdot \log_2(10^5)) \\
	&\approx O(10^5 \cdot 17) \\
	&\approx O(1.7 \cdot 10^6)
\end{align*}

Pertanto, considerando una macchina che esegue circa $10^8$ operazioni al secondo, il tempo stimato di esecuzione sarebbe:
\[
\frac{1.7 \cdot 10^6}{10^8} \text{ secondi } \approx 1.7 \cdot 10^{-2} \text{ secondi.}
\]

\noindent
In conclusione, il programma è coerente con il limite di tempo imposto dal problema (1.00 s).

\section{Anno Luce}

\href{https://training.olinfo.it/task/ois_annoluce}{Link al problema} 

\smallskip

\noindent Time limit = 1.00s, Memory limit = 256 MiB

\bigskip

Grazie ad una recente ricerca che ha confermato l’esistenza delle onde gravitazionali, sempre più persone si stanno interessando allo spazio. Purtroppo però, lo spazio è ancora una realtà poco accessibile alle persone comuni. Sebbene sia un po’ demoralizzato da questo fatto, William è convinto che sia possibile sfruttare la recente attenzione mediatica delle onde gravitazionali per pubblicizzare un business: ha deciso infatti di aprire una startup di viaggi interstellari.

\medskip
C’è da dire però che, a parte il Sole che è la stella a noi più vicina, le altre stelle sono piuttosto distanti.
Proxima Centauri, la “seconda stella più vicina”, dista dal Sole ben 4.24 anni luce: questo vuol dire che
sarebbero necessari più di quattro anni per raggiungere questa stella! (supponendo di poter viaggiare
alla velocità della luce).

\bigskip
William pensa di riuscire a costruire un’astronave in grado di viaggiare alla velocità della luce (ha trovato \href{https://www.youtube.com/watch?v=dQw4w9WgXcQ}{un tutorial su YouTube} che gli sembra piuttosto convincente) e ha perciò acquistato un telescopio per
tracciare una mappa 3D della Via Lattea. Ogni stella è indicata nella mappa 3D mediante un punto
$(x, y,z)$ dello spazio. Il Sole è sempre presente nella mappa ed è sempre identificato dal punto $(0,0,0)$.

\medskip
Scrivi un programma che data la mappa stellare sia in grado di rispondere a $Q$ query: ogni query fornisce un numero intero $D$ e chiede quante sono le stelle raggiungibili avendo a disposizione $D$ anni di viaggio.



\subsubsection*{Dati in input}  

Il file \verb|input.txt| è composto da $N+Q+2$ righe. La prima riga contiene l’unico intero $N$. Le successive $N$ righe contengono le coordinate $X_i$, $Y_i$, $Z_i$ dell’i-esima stella, separate da spazio. La successiva riga
contiene l’unico intero $Q$. Le successive $Q$ righe contengono i valori di $D$ delle relative query.

\subsubsection*{Dati in output}  

Il file \verb|output.txt| è composto da $Q$ righe contenente un intero ciascuna: la risposta alla relativa query.

\subsubsection*{Assunzioni e Vincoli}  


\begin{itemize}
	
	\item $1 \le N, Q \le 100\ 000$
	
	\item $0 \le X_i, Y_i, Z_i < 2^{30}$ per ogni $i = 0 \dots N-1$
	
	\item L’unità degli assi $x, y, z$ è l’anno luce
	
	\item $0 \le D < 2^{31}$ per ogni chiamata a \texttt{query(D)}
	
	\item Il valore $D$ è espresso in anni luce
	
\end{itemize}

Nel primo caso di esempio, le 3 stelle distano dal sole rispettivamente: $0$ anni luce,$\sqrt{3}$ anni luce e $2\sqrt{3}$ anni luce.
\bigskip

Nel secondo caso di esempio, le 5 stelle distano dal sole rispettivamente: $\sqrt{14}$ anni luce, $\sqrt{77}$ anni luce, $0$ anni luce, $9\sqrt{3}$ anni luce e $\sqrt{51}$ anni luce.


\subsubsection*{Idea (binary search)}

Si considera ciascun punto nello spazio tridimensionale con coordinate $(X_i, Y_i, Z_i)$.

Per ciascun punto:
\begin{itemize}
	\item si calcola la distanza dall'origine mediante la formula
	\[
	\text{distanza}_i = \sqrt{X_i^2 + Y_i^2 + Z_i^2};
	\]
	\item la distanza calcolata viene memorizzata in un vettore.
\end{itemize}

Una volta calcolate tutte le distanze, il vettore viene ordinato in modo crescente.  
Ciò permette di sfruttare la proprietà di monotonia: per ogni distanza \(D\) di una query, tutti i punti con distanza minore o uguale a \(D\) sono contigui all'inizio del vettore.

Per ciascuna query \(D[i]\):
\begin{itemize}
	\item si ricerca, tramite ricerca binaria, l'ultimo indice \texttt{best} tale che
	\[
	\text{distanza[best]} \le D[i];
	\]
	\item tutti i punti con indice compreso tra $0$ e \texttt{best} sono raggiungibili entro la distanza $D[i]$;
	\item il numero di punti raggiungibili è quindi \texttt{best + 1}.
\end{itemize}

Infine, per ciascuna query, il numero calcolato viene stampato in output su \texttt{output.txt}.


\subsubsection*{Implementazione C++ - Binary Search}


\begin{lstlisting}[language=C++]
#include <bits/stdc++.h>
using namespace std;

int main() {
	// Apriamo i file di input e output
	freopen("input.txt", "r", stdin);
	freopen("output.txt", "w", stdout);
	
	// Legge il numero di punti nello spazio
	int N;
	cin >> N;
	
	// Vettore di tuple per memorizzare le coordinate (X, Y, Z) di ciascun punto
	vector<tuple<int64_t, int64_t, int64_t>> coordinate(N);
	for(int i = 0; i < N; i++){
		cin >> get<0>(coordinate[i])  // leggi X
		>> get<1>(coordinate[i])  // leggi Y
		>> get<2>(coordinate[i]); // leggi Z
	}
	
	// Legge il numero di query
	int Q;
	cin >> Q;
	
	// Vettore per memorizzare i valori di distanza D per ciascuna query
	vector<int64_t> D(Q);
	for(int q = 0; q < Q; q++){
		cin >> D[q];
	}
	
	// Calcola la distanza dall'origine per ciascun punto
	vector<double> distanza(N);
	for(int i = 0; i < N; i++){
		// distanza: sqrt(X^2 + Y^2 + Z^2)
		double dist_q = powl(get<0>(coordinate[i]), 2) 
		+ powl(get<1>(coordinate[i]), 2) 
		+ powl(get<2>(coordinate[i]), 2);
		distanza[i] = sqrtl(dist_q);
	}
	
	// Ordina le distanze in ordine crescente
	sort(distanza.begin(), distanza.end());
	
	// Variabili per la ricerca binaria
	int high;
	int low;
	int best;
	
	// Ciclo per rispondere a ciascuna query
	for(int i = 0; i < Q; i++){
		low = 0;
		high = N - 1;
		best = -1; // inizializziamo l'indice del massimo elemento <= D[i]
		
		// Ricerca binaria per trovare l'ultimo indice con distanza <= D[i]
		while(low <= high){
			int mid = (low + high) / 2;
			
			if(distanza[mid] > D[i]){
				// La distanza è troppo grande: cerco a sinistra
				high = mid - 1;
			}
			else{
				// La distanza va bene: memorizzo mid come best e cerco a destra
				best = mid;
				low = mid + 1;
			}
		}
		
		// Tutti gli elementi da 0 a best sono raggiungibili
		int reach = best + 1;
		cout << reach << endl; // output del numero di punti raggiungibili
	}
	
	return 0;
}

\end{lstlisting}

\subsection*{Costo Computazionale}
Il costo computazionale è:
\begin{itemize}
	\item $O(\log N)$ per la ricerca binaria eseguita per ciascun indice $i$;
	\item $O(N)$ per il ciclo esterno che scorre tutti gli elementi del vettore.
\end{itemize}

Ciò significa che la ricerca binaria viene eseguita $N$ volte, una per ciascun elemento del vettore.

La complessità totale è quindi:
\begin{align*}
	&= O(N) \cdot O(\log N) \\
	&= O(N \log N)
\end{align*}

Dai vincoli del problema:
\[
1 \le N \le 10^5
\]

la complessità può essere stimata come:
\begin{align*}
	&\approx O(N \log N) \\
	&\approx O(10^5 \cdot \log_2(10^5)) \\
	&\approx O(10^5 \cdot 17) \\
	&\approx O(1.7 \cdot 10^6)
\end{align*}

Pertanto, considerando una macchina che esegue circa $10^8$ operazioni al secondo, il tempo stimato di esecuzione sarebbe:
\[
\frac{1.7 \cdot 10^6}{10^8} \text{ secondi } \approx 1.7 \cdot 10^{-2} \text{ secondi.}
\]

\noindent
In conclusione, il programma è coerente con il limite di tempo imposto dal problema (1.00 s).

\section{U. Factory Machines}

\href{https://codeforces.com/gym/102961/problem/U}{Link al problema} 

\smallskip

\noindent Time limit = 2.00s, Memory limit = 256 megabytes

\bigskip

A factory has n machines which can be used to make products. Your goal is to make a total of t products.

\medskip
For each machine, you know the number of seconds it needs to make a single product. The machines can work simultaneously, and you can freely decide their schedule.

\medskip
What is the shortest time needed to make t products?



\subsubsection*{Input}  

The first input line has two integers $n$ and $t$: the number of machines and products.

\subsubsection*{Output}  

Print one integer: the minimum time needed to make $t$ products.

\subsubsection*{Constraints}  


\begin{itemize}
	\item $1 \le n \le 2 \cdot 10^5$
	\item $1 \le t \le 10^9$
	\item $1 \le k_i \le 10^9$
\end{itemize}
	


\subsubsection*{Example}

	\setlength{\tabcolsep}{12pt} % aumenta lo spazio orizzontale tra le colonne

		\hline
		\multicolumn{1}{|c|}{\textbf{input}} & \textbf{output} \\ \hline

\subsubsection*{Idea (binary search)}

Si considerano $n$ macchine, ciascuna con tempo $k_i$ necessario per produrre un prodotto, e un obiettivo di $t$ prodotti totali.

Per ciascuna macchina:
\begin{itemize}
	\item si calcola quanti prodotti può produrre in un certo tempo $T$ tramite
	\[
	\text{prodotti}_i = \frac{T}{k_i};
	\]
	\item i prodotti vengono sommati a un contatore totale.
\end{itemize}

Il problema si riduce a trovare il tempo minimo $T$ tale che la somma dei prodotti di tutte le macchine sia almeno $t$.

Per trovare questo tempo minimo si applica una \textbf{ricerca binaria}:
\begin{itemize}
	\item si definiscono due estremi: \texttt{low} = 0 e \texttt{high} = un limite superiore sufficiente (ad esempio $10^{18}$. Infatti, questo rappresenta il tempo massimo, poiché corrisponde al tempo necessario affinché tutti i prodotti vengano realizzati da un’unica macchina, ovvero quella più veloce);
	\item si calcola la metà \texttt{mid} = \texttt{low} + (\texttt{high} - \texttt{low}) / 2 (calcolato in questo modo "strano" per impedire l'overflow che sarebbe dato da $low + high$);
	\item si valuta quanti prodotti possono essere fatti in \texttt{mid} tempo tramite la funzione di simulazione;
	\item se il totale è minore di $t$, allora il tempo non è sufficiente e si aggiorna \texttt{low = mid + 1};
	\item altrimenti, \texttt{mid} è un candidato valido e si prova a diminuire il tempo aggiornando \texttt{high = mid - 1}.
\end{itemize}

Alla fine della ricerca binaria, il valore minimo valido di \texttt{mid} rappresenta il tempo minimo necessario per produrre almeno $t$ prodotti, e viene stampato in output.


\subsubsection*{Implementazione C++ - Binary Search}


\begin{lstlisting}[language=C++]
#include <bits/stdc++.h>
using namespace std;

// Funzione che calcola quanti prodotti possono essere fatti in un certo tempo
// "tempo" = tempo totale disponibile
// "N" = numero di macchine
// "k" = vettore dei tempi per produrre un prodotto per ciascuna macchina
// "prodotti" = numero di prodotti richiesti
int64_t simula(int64_t tempo, int N, vector<int> &k, int64_t prodotti){
	int64_t acc = 0; // contatore dei prodotti fatti
	for(int i = 0; i < N; i++){
		acc += tempo / k[i]; // la macchina i produce tempo/k[i] prodotti
		// se abbiamo gia' raggiunto o superato i prodotti richiesti, smettiamo
		if(acc >= prodotti){
			return acc;
		}
	}
	return acc; // ritorna quanti prodotti sono stati fatti in "tempo"
}

int main(){
	int n;           // numero di macchine
	int64_t t;       // numero di prodotti richiesti
	cin >> n >> t;   
	
	vector<int> k(n);   // tempi per ciascuna macchina
	for(int i = 0; i < n; i++){
		cin >> k[i];   
	}
	
	// Binary search: vogliamo trovare il tempo minimo in cui possiamo fare almeno t prodotti
	int64_t ans = -1;      // qui salveremo la risposta
	int64_t low = 0;        // tempo minimo possibile
	int64_t high = 1e18;    // tempo massimo possibile (un limite molto grande, sicuro)
	
	while(low <= high){
		// calcolo sicuro della meta' senza rischio overflow
		int64_t mid = low + (high - low) / 2;
		
		// calcolo quanti prodotti possiamo fare in "mid" tempo
		int64_t prodotti_finiti = simula(mid, n, k, t);
		
		if(prodotti_finiti < t){
			// se non bastano, dobbiamo aumentare il tempo
			low = mid + 1;
		}
		else{
			// se bastano, questo è un candidato valido
			ans = mid;
			// proviamo a trovare un tempo ancora piu' piccolo
			high = mid - 1;
		}
	}
	
	cout << ans << endl; 
}

\end{lstlisting}


\subsection*{Costo Computazionale}

Il costo computazionale è:

\begin{itemize}
	\item $O(\log T_\text{max})$ per la ricerca binaria sul tempo minimo necessario, dove $T_\text{max}$ è il limite superiore del tempo;
	\item $O(N)$ per la funzione \texttt{simula}, che scorre tutte le $N$ macchine per calcolare quanti prodotti vengono prodotti in un dato tempo.
\end{itemize}

Poiché la ricerca binaria viene eseguita su un intervallo di dimensione $T_\text{max}$ e ad ogni step si valuta la funzione \texttt{simula}, la complessità totale è:

\begin{align*}
	&O(N) \cdot O(\log T_\text{max}) \\
	&= O(N \log T_\text{max})
\end{align*}

Dai vincoli del problema:

\[
1 \le N \le 2 \cdot 10^5, \quad T_\text{max} \approx 10^{18}
\]

la complessità può essere stimata come:

\begin{align*}
	&\approx O(2 \cdot 10^5 \cdot \log_2(10^{18})) \\
	&\approx O(2 \cdot 10^5 \cdot 60) \\
	&\approx O(1.2 \cdot 10^7)
\end{align*}

Pertanto, considerando una macchina che esegue circa $10^8$ operazioni al secondo, il tempo stimato di esecuzione sarebbe:

\[
\frac{1.2 \cdot 10^7}{10^8} \text{ secondi } \approx 0.12 \text{ secondi.}
\]

\noindent
In conclusione, il programma è ampiamente coerente con il limite di tempo imposto dal problema (2.00 s).
